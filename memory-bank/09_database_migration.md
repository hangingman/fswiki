# データ移行方針

## 現在

Raku版は既存FSWikiの`data/*.wiki`を`FSWiki::Storage::File`で読む。CoreはStorage APIへ委譲する。

## 移行順序

1. File Storageで既存データを読み書きする。
2. ページ保存、エンコード、バックアップ、履歴の要件を確認する。
3. Raku側のStorage契約を固定する。
4. 必要になった段階でDB Storageを追加する。
5. 移行ツールと整合性検証を実装する。
6. 本番移行先とバックアップ方式を決める。

## 方針

- DBを先に導入しない。
- TiDBを前提にしない。Fly.ioを含む実行環境の永続ボリューム、外部DB、バックアップ費用を比較して決める。
- 移行中はPerl版の`data`を変更せず、Raku版の読み取り確認を優先する。
- データ移行の実施時は件数、ページ名、本文ハッシュ、履歴、添付ファイルを個別に検証する。
